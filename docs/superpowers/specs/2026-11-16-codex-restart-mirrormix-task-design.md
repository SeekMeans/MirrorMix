# Codex 一键重启 MirrorMix 任务设计

日期：2026-11-16

## 目标

在 Codex 桌面应用中建立一个独立任务「重启 MirrorMix」。用户手动运行该任务时，任务只重启 `E:\Me\AIMiss` 的 MirrorMix 服务，并明确报告结果。

## 范围与边界

- 目标目录固定为 `E:\Me\AIMiss`。
- 服务端口固定为 `4789`，健康检查地址为 `http://127.0.0.1:4789/api/health`。
- 仅停止监听该端口的进程；不按进程名称广泛结束 Node、Codex 或其他应用。
- 重启使用项目既有命令：先构建前端，再以后台进程运行服务端。
- 任务不改写项目源码、配置或会话记录。
- 任务由用户手动触发；不设置定时运行或崩溃自动重试。

## 执行流程

1. 确认项目目录、`package.json` 与 Node/npm 可用。
2. 查询 `127.0.0.1:4789` 的监听进程；如果存在，只结束该进程。
3. 在项目目录运行 `npm run build`。构建失败时立即报告失败，不启动新服务。
4. 以隐藏后台 PowerShell 进程启动 `npm run dev`，把标准输出和错误输出写入项目下的运行日志文件。
5. 最多等待 20 秒，轮询 `/api/health`。
6. 健康检查成功时，报告访问地址、后台进程号与日志位置；超时或启动失败时，报告最近日志和下一步诊断信息。

## 任务提示词与安全约束

Codex 任务的固定指令会要求它严格执行上述流程，不接收或拼接用户提供的 shell 片段，不变更服务监听地址，也不终止未监听 4789 端口的进程。它将使用 PowerShell 的 `Get-NetTCPConnection` 和 `Stop-Process -Id`，且只在确认到准确进程号后停止。

## 验收与失败处理

- 成功条件：重启后 `/api/health` 返回 JSON 且包含 `ok: true`。
- 端口无人监听：跳过停止步骤，直接构建并启动。
- 构建失败：保留旧服务已停止的事实，返回构建输出，不伪报成功。
- 启动超时：返回后台进程号、日志末尾和健康检查失败结果。
- 权限不足或端口被其他程序重新占用：不尝试扩大清理范围，直接报告冲突。

## 测试方式

首次创建任务后，手动运行一次，确认：旧的 4789 监听者被替换、健康检查成功、网页可打开，并且任务输出包含新的进程号和日志路径。
